# Spec Delta

## Purpose

为设定、人物、大纲等小说资料提供工程化管理视图（角色卡、设定关联图谱、大纲剧情线）。`.md` 文件始终是唯一事实来源，结构化视图是对资料的可读写投影。

## ADDED Requirements

### Requirement: 角色卡视图
系统 SHALL 以角色卡形式展示 `concept/` 下的人物资料：每张角色卡呈现人物的核心属性（姓名、身份、关系、状态摘要等），支持在卡片视图中编辑并写回对应 Markdown 文件。

#### Scenario: 查看角色卡列表
- **WHEN** 用户进入角色管理视图
- **THEN** 系统展示由 `concept/` 人物资料生成的角色卡列表

#### Scenario: 编辑角色卡写回文件
- **WHEN** 用户在角色卡上修改人物属性并保存
- **THEN** 变更写回对应的 Markdown 文件，文件内容与卡片展示保持一致

### Requirement: 设定关联图谱
系统 SHALL 提供设定关联图谱视图：以人物、设定条目为节点，以资料中声明的关联（人物关系、设定引用）为边构成可交互图谱；用户可从节点定位并打开对应资料文件。

#### Scenario: 生成图谱
- **WHEN** 用户打开关联图谱视图
- **THEN** 系统基于当前作品资料渲染节点与关联边

#### Scenario: 从节点定位文件
- **WHEN** 用户点击图谱中的某个节点
- **THEN** 系统展示该节点对应资料摘要，并可打开其源 Markdown 文件

### Requirement: 大纲剧情线视图
系统 SHALL 提供剧情线视图：从 `outline/` 资料与章节中提取的剧情线按章节顺序展示进展，用户可查看每条剧情线涉及的章节与当前状态。

#### Scenario: 查看剧情线进展
- **WHEN** 用户打开剧情线视图
- **THEN** 系统展示各剧情线及其关联章节的推进情况

### Requirement: 单一事实来源
所有结构化视图 MUST 以对应 `.md` 文件为唯一事实来源：视图编辑写回文件；文件被外部修改后，视图基于最新文件内容刷新，不维护独立的数据副本。

#### Scenario: 视图编辑写回
- **WHEN** 用户在任意结构化视图中保存修改
- **THEN** 对应 `.md` 文件同步更新，且再次打开视图时显示的是文件派生的最新内容

#### Scenario: 外部修改后视图同步
- **WHEN** 作品资料文件在应用外被修改
- **THEN** 结构化视图刷新后反映外部修改后的内容

### Requirement: 资料索引缓存
结构化视图所依赖的解析索引 SHALL 缓存于作品 `.novel/` 目录以加速加载，并支持用户手动重建；缓存损坏或缺失时系统 MUST 能从源文件完整重建。

#### Scenario: 手动重建索引
- **WHEN** 用户触发索引重建
- **THEN** 系统重新解析资料文件并更新缓存，视图内容随之刷新

#### Scenario: 缓存缺失时降级
- **WHEN** 打开视图时缓存不存在或不完整
- **THEN** 系统从源文件重新解析生成视图，不因缓存缺失而失败
